# Disaster Recovery Playbooks (`DR-01` through `DR-12` — `RISK-41`)

All 12 Disaster Recovery runbooks below are codified and GameDay-verified by `stage2-runner` (`pkg/observability/observability.go`).

---

## `DR-01`: Single Cell Hardware Loss (`Zone A` NVMe/VM Destruction)
- **Trigger:** Multi-vantage Control Plane probers observe `3 × 1s` consecutive health probe failures (`ALERT-13` / Cell `DEAD`).
- **Automated Action:**
  - **Pro Sync Tier:** Control Plane acquires `SELECT ... FOR UPDATE` on tenant row, increments `epoch = E + 1`, executes Standby Pre-Fence + `pg_ctl promote` on Zone B Standby (`RPO = 0`), updates Gateway route cache, and schedules a replacement Standby in Zone C.
  - **Standard Async Tier:** Control Plane waits the mandatory **`12.0s` monotonic fencing barrier** (guaranteeing isolated Primary self-killed at `<= 8.0s`), restores latest verified R2 base + incremental + WAL chain onto healthy Cell C (`RPO <= 5s`), and commits `epoch = E + 1`.
- **Verification Gate:** `SELECT pg_is_in_recovery() == false` and `epoch == E + 1`.

## `DR-02`: Whole Fly Region Evacuation (`iad -> ewr/ord`)
- **Trigger:** Regional outage in primary Fly region (`iad`) confirmed by external synthetic probers.
- **Automated / Scripted Action:**
  1. Provision replacement Compute Cells in backup region (`ewr` or `ord`) using stepped `ext4` volumes.
  2. Query Control DB (or cold-bootstrapped R2 metadata snapshot) for tenant priority order (`Pro HA -> Paid Starter -> Free`).
  3. Hydrate tenants from Cloudflare R2 (`pg_combinebackup` + `pg_verifybackup` + WAL replay) using bounded concurrency (`max_concurrent_starts = 5` per Cell).
  4. Update `pg-gateway` regional Anycast routing table and increment `epoch++`.
- **Verification Gate:** `pg_verifybackup == 0` + `pg_amcheck == 0` across evacuated fleet.

## `DR-03`: Cloudflare R2 Outage WAL Buffering & Spool Drain
- **Trigger:** `ALERT-12` (`R2UploadErrorSpike` `5xx` / timeout).
- **Automated Action:**
  1. `pg-cell-agent` switches WAL archiver to local spool directory `/vol/spool/wal/{tenant_id}/` (encrypted with tenant DEK + AAD prior to disk write).
  2. If `/vol` usage approaches `85%`, throttle bulk writers before touching `.cell_ballast`.
  3. Upon R2 recovery, background drain worker uploads spooled segments in strict LSN order with `If-None-Match: "*"` before unlinking local spool files.
- **Verification Gate:** `d3_remaining_local_spool_post == 0` and unbroken WAL LSN continuity in R2.

## `DR-04`: Pro Standby Disconnection Resolution & Re-Seed
- **Trigger:** `ALERT-11` (`ProSyncStandbyLost` `> 10s`).
- **Automated Action:**
  1. Primary commits block safely inside `SyncRepWaitForLSN` (preserving strict `CP` `RPO = 0` contract).
  2. If Standby reconnects within grace window, streaming replication resumes automatically and unblocks `SyncRepWaitForLSN`.
  3. If Standby host is permanently lost, either promote Standby (if Primary died) or rebuild a replacement Standby in a distinct zone via `pg_basebackup -R -X stream`.
- **Verification Gate:** `pg_stat_replication.sync_state == 'sync'` and `flush_lsn >= current_wal_lsn`.

## `DR-05`: Control Plane 3-Node HA Postgres Failover & Cold R2 Metadata Bootstrap
- **Trigger:** `ALERT-13` (`ControlPlaneMetadataDBDown`).
- **Automated Action:**
  1. Patroni / 3-node HA Metadata DB promotes synchronous standby replica in `< 5s`.
  2. If total metadata cluster loss occurs, bootstrap fresh Control DB from the encrypted hourly R2 `control-metadata/` snapshot + reconcile live Cell `/vol/tenants/active/*` inventories against R2 `manifest.json` epochs.
- **Verification Gate:** `UNIQUE(tenant_id)` and `UNIQUE(system_identifier)` constraints verified intact.

## `DR-06`: 7-Day Soft-Delete Accidental-Delete PITR Recovery
- **Trigger:** Customer support / API request `POST /v1/databases/{id}/restore-deleted` within 7 days of `DELETE`.
- **Automated Action:**
  1. Verify cluster state is `SOFT_DELETED` and tenant `DEK` is still intact in KMS.
  2. Run Flow 8 PITR restore from R2 using preserved `DEK`, rotate `SCRAM-SHA-256` password, and transition state to `ACTIVE (epoch = E + 1)`.
- **Verification Gate:** Restored cluster passes `pg_verifybackup` and `SELECT count(*)` row check.

## `DR-07`: Corrupted Snapshot Fallback to Prior Verified Base Chain
- **Trigger:** `ALERT-08` (`pg_verifybackup_failures_total > 0`) during backup or restore.
- **Automated Action:**
  1. Immediately discard the failed staging backup directory and abort any incomplete R2 multipart upload.
  2. Traverse Control DB `backups` DAG backward to the previous `VERIFIED` full/incremental chain (`parent_manifest_id`) and schedule a fresh full `pg_basebackup`.
- **Verification Gate:** Fallback chain passes `pg_verifybackup` and `DEK` unwrap test.

## `DR-08`: Corrupted WAL Fail-Closed Truncation Notification
- **Trigger:** PITR `restore_command` encounters corrupted/missing `.wal.zst.enc` segment or GCM authentication tag failure.
- **Automated Action:**
  1. **Fail closed immediately** (NEVER set `recovery_target_action = 'promote'` past a missing/corrupted WAL gap!).
  2. Halt recovery and emit structured operator alert + customer notification reporting the exact last valid contiguous LSN and timestamp (`last_valid_lsn`).
- **Verification Gate:** Zero silent transaction holes; recovery aborts deterministically on corrupted WAL segment.

## `DR-09`: Returning Stale Primary Quarantine & Cleanup (`FENCED_QUARANTINE`)
- **Trigger:** Partitioned Cell #1 reconnects to Control Plane with `local_epoch < control_db.current_epoch`.
- **Automated Action:**
  1. Monotonic `8.0s` watchdog has already killed local `postgres`.
  2. Control Plane rejects heartbeat from stale epoch and sends `QuarantineAndPurge(tenant_id, stale_epoch)`.
  3. Cell Agent transitions local directory to `/vol/tenants/quarantine/{tenant_id}_epoch_{e}`, releases `agent.lock`, and purges stale `PGDATA` after forensic snapshot check.
- **Verification Gate:** `0` processes running for stale epoch; R2 rejects any stale epoch upload with `412 PreconditionFailed`.

## `DR-10`: Aborted Live Migration Replication Slot Cleanup
- **Trigger:** Target Cell crashes mid-Flow-11 physical migration before `epoch++` cutover.
- **Automated Action:**
  1. Source Primary remains active (`epoch` unchanged, `0` customer downtime).
  2. Reconciler executes `SELECT pg_drop_replication_slot('mig_slot_' || tenant_id)` on Source Primary so WAL never accumulates up to `max_slot_wal_keep_size` (`256MB`), and sweeps `/vol/tenants/claiming/*` on Target Cell.
- **Verification Gate:** `SELECT count(*) FROM pg_replication_slots WHERE slot_name LIKE 'mig_slot_%' == 0`.

## `DR-11`: Bulk Secret & Master `KEK` Envelope Re-Wrapping Rotation
- **Trigger:** Scheduled 90-day security rotation or incident response.
- **Automated Action:**
  1. Generate new 256-bit Master `KEK_v2` in KMS.
  2. Iterate over wrapped per-tenant `DEK` records in Control DB: unwrap each 32-byte `DEK` using `KEK_v1` and immediately re-wrap with `KEK_v2` (`O(1)` metadata operation per tenant—**zero R2 backup/WAL objects need to be downloaded or re-encrypted**!).
  3. Verify `DecryptObject` succeeds using `KEK_v2` and zeroize `KEK_v1`.
- **Verification Gate:** Historical R2 ciphertext decrypts identically under `KEK_v2` (`0` R2 bytes re-uploaded).

## `DR-12`: Staggered Priority-Ordered Mass-Cell Fleet Recovery (`max_concurrent_starts = 5`)
- **Trigger:** Whole-Cell reboot or mass wake storm across 50+ tenants on one host.
- **Automated Action:**
  1. Cell Agent orders tenants by priority tier (`Pro Sync -> Paid Starter -> Free`).
  2. Acquires bounded startup semaphore (`max_concurrent_starts = 5`) so at most 5 `pg_ctl start` processes run simultaneously, preventing NVMe IOPS and CPU thundering-herd starvation.
- **Verification Gate:** Peak concurrent `pg_ctl start` invocations `<= 5`; `100%` of priority tenants reach `ACTIVE`.
