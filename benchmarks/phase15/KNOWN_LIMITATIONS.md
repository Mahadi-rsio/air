# AIR Phase 15 — Known Limitations (`KNOWN_LIMITATIONS.md`)

1. **B-Tree Index Scan Operators**: `btree.go` pushes down `EQ`, `GT`, `GE`, `LT`, and `LE` on leading index key columns. `NE`, `IS NULL`, and `IS NOT NULL` constraints are pushed to `air_pg` residual filter evaluation rather than B-tree range bounds, and `IN` / `OR` lists rely on SQLite's virtual-table / query-plan handling or residual filtering.
2. **Join Execution Engine**: AIR delegates join ordering and join algorithm execution (nested loop, automatic transient indexing) to SQLite's query planner, informed by AIR's `xBestIndex` `estimatedCost` and `estimatedRows`. No custom Go hash-join or merge-join operator was added because benchmarks showed SQLite's native join engine already handles supported read joins without duplicating execution code.
3. **Histograms & MCV Lists**: `DiscoverCatalog` reads `pg_class` (`relpages`, `reltuples`, `relallvisible`) and `pg_statistic` (`stanullfrac`, `stawidth`, `stadistinct`). Full MCV array and histogram-bound decoding from `pg_statistic` `anyarray` slots is deferred; conservative selectivity bounds are used for range predicates.
4. **Index-Only Heap Bypass**: Because PostgreSQL visibility-map (`VM`) pages are not yet consulted per block in `air_pg`, index scans still validate heap tuple MVCC visibility and HOT-chain TIDs to preserve strict snapshot correctness.
5. **PostgreSQL 15 Binaries**: Only PostgreSQL `17.12` server binaries are installed in this environment, so `TestPhase13_PG15_WALReceiver_CatalogAndQuery` skips while `TestPhase15_LivePG17_EndToEnd` runs against live PostgreSQL `17.12`.
